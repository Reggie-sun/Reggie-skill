# 每天一个 AI 神器：选题卡、证据与验收

这是 daily-ai-tool-demo-video/SKILL.md 的按需参考。与周报的 news rhythm 案例不同，本栏目核心证据是“观众能看到、能复现”的一次具体使用。

## A. 每日 5 个候选的输出模板

候选不足 5 个则如实给更少，按 **可视化效果 → 用户实际收益 → 上手门槛 → 近期热度** 综合排序。

每个工具都应包含：

| 字段 | 必须回答 |
| --- | --- |
| 名称与功能 | 用一句普通话说明“它帮哪类人做成哪件事”；不要堆模型和跑分 |
| 使用入口 | 产品可用的准确地址；若为 App 则标明平台与入口 |
| 对应消息 | 官方发布/更新原文地址；发生、更新、报道日期分开 |
| 目前能不能用 | 中国大陆/其他地区，网页/App，注册、邀请码/灰度、付费、免费额度/水印 |
| 最容易拍的功能 | 一个具体任务、输入素材、输出样式、预计演示镜头 |
| 传播钩子 | 真实、直观、让观众想试，尽量从结果出发 |
| 证据级别 | 亲测成功 / 已核官方演示 / 仅产品宣称 / 尚未确认 |
| 与周报关系 | 仅日更、仅周报、两者可用但切入点不同；避免复述 |
| 综合判断 | 首推/备选/暂不拍，以及风险或下一步验证 |

候选表可以私下用于排序；用户说“给我链接和对应消息”时，展示可点击的使用入口与消息原文，不只给工具名称或 API 文档。

### 候选排序参考

不是硬性总分。出现任何“核心功能无法证明”“费用和入口不明”“不能展示结果”“用户根本无法获得”的问题，可直接降级，不受热度影响。

- **强首推**：普通观众看 3 秒结果就知道有什么用；可真实演示；入口易用且信息可信。
- **备选**：有明确价值，但演示不够直观、需要登录/付费、或者地区/灰度限制较多。
- **不建议拍**：只有行业新闻；仅模型参数和基准测试；官方演示或真实操作均不存在；需虚构输出才能体现价值。

## B. 单工具实测记录（拍视频前填写）

为当日选中的工具建立一张简短“证据卡”：

- 工具与版本：
- 采集日期、当时访问地区/设备：
- 原始官方入口与功能更新来源：
- 演示任务与目标用户：
- 测试输入（脱敏/自制文件）：
- 真实操作步骤（UI 字样尽量原样）：
- 结果素材文件/录屏片段：
- 关键观察（成功、失败、水印、耗时、导出限制）：
- 付费情况与需要说明的条件：
- 允许用于视频的画面来源及授权：
- 哪句口播由哪一段操作或哪条官方来源证明：
- 是否与最近的《一周 AI 大事》共用主题，差异在哪里：

若某项尚未核实，不要从新闻稿猜答案。未实际操作就不能在证据卡里填“实测成功”。

## C. 口播与分镜参考（约 45 秒）

这个例子只是结构示意，不指称某款真实产品已具备功能：

| 时间 | 观众看到什么 | 口播目标 |
| --- | --- | --- |
| 0–3 秒 | 同一张图片处理前后的并排对比；真实输出占满视线 | 一个具体结果，“这是原图，这是我处理后的样子” |
| 3–8 秒 | 原图和痛点近景 | 谁会遇到、为什么麻烦 |
| 8–16 秒 | 打开可用的产品页面并找到正确功能 | 给出可复现入口 |
| 16–31 秒 | 上传测试图、真实输入、执行操作 | 操作中只讲关键步骤，不念菜单 |
| 31–38 秒 | 输出结果与原图放在同条件下比较 | 效果说话，不以单例推断全部成功 |
| 38–45 秒 | 在实际界面指出当前费用或限制 | 说清试用门槛和适用场景 |

可以根据实际生成耗时或镜头价值调节。不要把“显示结果”剪得比“工具名称大字”还短，也不要把所有操作浓缩成静态 PPT。

### 好的标题和不好的标题

- 具体、有证据：**“5 分钟会议录音，AI 帮我整理成这张待办清单”**（必须实际测试结果和时间描述成立）。
- 单纯新闻化：**“某公司正式发布 XX 2.0，功能再升级！”**（不符合日更栏目的核心价值）。
- 不可接受的夸大：**“所有人永久免费、一键替代设计师、准确率 100%”**（除非能严格支持，否则禁止）。

## D. 作品随附资料

制作档最终应交付：

1. 可播放视频（以及用户要求的源工程），默认 9:16；若用户另有明确画幅沿用既定画幅。
2. 3 个可选封面/标题方案与实际使用的那一个。
3. 口播稿与字幕文件（如果已经渲染）、对应时间码的镜头清单。
4. **官网使用入口**、**发布/更新的原始消息**、实测日期和重要限制，可直接贴在作品简介或置顶评论。
5. 若有任何步骤只用官方演示或原创示意，明确标注，不以“我实测了”叙述。
6. 已核验的文件名、保存路径和制作方式；不要提供并不存在的附件或文件链接。

## E. 最终验收清单

- [ ] 标题兑现了开头所展示的结果，不是“骗点进来”。
- [ ] 观众在前 3 秒看到了结果、对比或具体悬念，而不是纯 Logo。
- [ ] 产品入口不是新闻报道或仅供开发者使用的 API 文档。
- [ ] 对应消息提供日期准确的来源，“新发布”和“新报道”没有混淆。
- [ ] 实测、官方演示、宣传性描述严格区分。
- [ ] 画面展示真实完整的关键操作，结果和输入可对上。
- [ ] 功能的免费、订阅、邀请码、地区、设备和水印限制没有隐瞒。
- [ ] 没有未经授权的支付、敏感数据上传、第三方账号登录或绕过限制。
- [ ] 画面在手机上看得清，字幕不挡操作，素材有合法使用依据。
- [ ] 阿虎配音和字幕同步，读音与价格数字准确，音画完整。
- [ ] 与周报即使出现同款工具，仍提供独特的操作证据和观看价值。
- [ ] 用户要求的文件已真实生成，不能靠一份制作建议宣称“完成视频”。

## F. 最小验收样例

**测试 1｜只有新闻，没有录屏**
给一个最新模型发布链接：可以写“有潜在用途”的候选，但不能强行入选“亲自实测的神器”；应寻找可验证产品入口和具体任务，或放入周报。

**测试 2｜产品可用但不是新品**
给一个数月前推出、今天仍很好用的工具：只要有明确实用性和演示，就可入选；明确说明“非本周新品”，而不是为新鲜感伪造发布时间。

**测试 3｜功能可用但有邀请码**
应该说明当前使用门槛；如果没有资格，只能展示标注为官方演示的素材，不能拍“人人三步上手”。

**测试 4｜与周报重复**
周报已经介绍“视频模型升级 30 秒生成”。日更如果能真实演示“一张照片如何做成 30 秒片段”和实际成本，可入选；若只有新闻通稿和同一段官方视频，则拒绝。

**测试 5｜没有制作环境**
输出完整候选、核实证据和可执行脚本/分镜，并明确没有录屏/渲染；不能声称已交付视频。
