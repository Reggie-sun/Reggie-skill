# 每天一个 AI 神器：从工具发现到可发布视频

## 0. 栏目定位与触发

- 适用：“今天推荐几个实用 AI 工具”“每天一个 AI 神器”“把这个 AI 工具做成抖音短视频”“给奇点来信做一条实测教程”。
- 目标观众：不懂模型架构、只关心是否能立刻解决生活/工作/创作问题的普通人。内容优先回答“**能帮我做什么？效果到底如何？我能否用、多少钱、怎么用？**”。
- 不做另一个 AI 新闻栏目。周报 Skill（../weekly-ai-news-vertical-video/SKILL.md）负责“本周发生了什么、为什么重要”；本 Skill 负责“亲自用它完成一件具体的事”。同一产品可以两边出现，但**叙事、核心证据、观众收益不能重复**。
- 优先近期发布/更新/走红的产品，但**不强制新品**；有用、可用、能演示比“今天刚发布”重要。不要把旧功能伪装成新功能。
- 分两种任务：
  - **选题档**：用户要求推荐时，每天给约 5 个候选及完整双链接、用途、限制、视频钩子，按适合普通观众且能实拍的程度排序；验证不足就减少数量，不硬凑。
  - **制作档**：选择最值得拍的 1–2 个，各做一条独立 30–60 秒视频；不要把 5 款工具拼成另一条资讯快报。用户只要求选题时不要擅自渲染视频。
- 继承已有周报的**先出样片、用户确认后再全片**习惯；若用户明确要求直接交付成片，则执行完整制作和自检，不把“先等确认”当作借口。
- 视频内容中所有事实、产品功能、价格与可用性必须可追溯；口播可以有噱头，但不能把宣传素材说成亲测，不能用“免费”“无限”“人人可用”“一键”等未经核实的绝对词。

## 1. 当日发现与事实核实

每次执行都要查最新信息，记录核实日期；不依赖过期榜单、二手短视频口播或搜索摘要直接写稿。

1. 从图片/视频、办公、学习、生活、求职、电商/内容创作等场景寻找约 5 个候选；优先国内观众**实际可访问**、无需复杂部署、可展示前后结果的工具。
2. **至少区分两种链接**：
   - **产品使用入口**：可打开的官网、App 页面或正式产品入口，不能拿 API 文档或媒体报道冒充购买/使用地址。
   - **对应消息来源**：官方发布说明、更新日志、产品博客；官方无日期时用可信媒体并说明“报道于”，不能把报道日期写成上线日期。
3. 实际核对：功能是否已上线、哪些账号/平台/地区可用、是否内测/邀测、是否付费、免费额度与水印/导出限制。未知就是未知，不猜。
4. 对每一项能力记录“产品宣称 / 官方演示 / 我们实际操作验证”三种证据级别。只有亲自成功操作后才能写“实测成功”。
5. 拒绝：只有技术跑分、没有普通人使用场景、找不到可访问入口、无法证明关键效果、涉嫌盗版或高风险的工具。若只是邀测或无法体验，可放备选，不作为“普通人立刻上手”的首推。
6. 在候选之间查重：同一工具旧闻、近期已做的视频、以及当期周报主题。重合不是绝对禁用，但必须有**不同的实操价值**；不要用同一素材换标题反复发布。

候选表必须覆盖：名称、解决的一个具体问题、可用入口 URL、消息/更新来源 URL 与日期、当前可用性及费用、演示可行性、3 秒钩子、推荐优先级和是否与周报重复。记录在随片的选题资料里；用户要看候选时展示，不必为了让用户确认而先发送大段内部资料。

## 2. 一定要先有可复现的“结果镜头”

- 先选**一件普通人能看懂的任务**，例如“去掉照片背景路人”“把录音变会议纪要”“让一张商品图变短视频”。用一份不涉及隐私、可重用的测试输入完成一次完整操作。
- 如可访问并获授权，可用 Playwright/真实 UI 录屏：入口 → 输入 → 生成/处理 → 输出。优先亲自体验；录屏须保留足够完整的操作和真实等待过程，不伪造成功率与耗时。
- 账号登录、上传真实私人资料、付费、提交订单、公开发布、授权敏感权限等，需要已有明确授权；否则用公开试用或安全示例，不获取或使用 cookie 绕过认证，不因做演示而花钱。
- 无法亲测时只采用**标明为官方演示**的真实动态素材；可以做客观“工具介绍”，但不得冒充实测。缺少可信效果演示的选题降级或不选。
- 结果应能**一眼看出差异**。保留“输入与输出”的对应关系；对比条件相同，不能用不相干图片当作生成效果。记录工具/版本/提示词/输入/输出、录制时间和真实限制，确保下一次可复现。
- 有重要短板也要如实表现：收费、水印、处理失败、地区限制、复杂操作或效果不稳定，不只剪成功片段营造普遍可靠的错觉。

## 3. 选题原则与短视频脚本

从观众收益反推标题，不从模型名称和发布会反推标题。

优先顺序：
- **看一眼就想试**：结果出乎意料，有清晰前后对比；
- **切身价值**：省时间、减少重复劳动、学习/求职/创作更简单；
- **容易复现**：入口清晰、步骤少、成本透明；
- **适合视频**：真实操作过程本身在发生变化；
- **消息新鲜**：近期更新是加分项，不是替代实用性的硬门槛。

默认一条只讲一个工具、一个高价值用途、一个完整演示。口播目标 30–60 秒，可随完整操作的实际节奏调整，不为卡秒数删关键步骤：

1. **0–3 秒：先给结果或强问题**。能放真实对比就先放，少用“某公司推出了XX”“AI圈炸了”。钩子不承诺未实现的效果。
2. **3–12 秒：具体痛点**。普通用户为什么要关心。
3. **12–40 秒：实际操作**。入口、最少关键步骤、输入输出连贯展示。允许保留操作原声片段，别全靠静图配口播。
4. **40–55 秒：效果与限制**。说清哪些可用、要不要付费、什么时候不值得用。
5. **最后几秒：自然收尾**。可以提示工具入口在文字介绍里；不强制“关注三连”“评论区扣1”等空洞互动。

以上是节奏参考，不是分镜秒数硬约束。写稿应参考真实实操效果，不为了好听虚构步骤和成本。要让不看字幕的人只听口播也能明白结果；不要在旁白里逐字读产品发布说明。

每条产物含：3 个可用标题、选定标题、封面短句、前 3 秒钩子、可直接配音的完整中文脚本、逐镜头真实素材映射、置顶评论/作品说明中可用的官方入口与限制。优先把**视频作品**交给用户，不能用长篇选题分析代替成片。

## 4. 视觉与节奏

- 默认**抖音原生竖屏 9:16，1080×1920 / 30fps**。与周报默认 16:9 不同：日更教程通常需要让手机观众看清操作；若用户明确给了横屏模板或本栏目已有已认可版式，则按用户已定的版式，而不是盲改。
- 必须有清晰动态效果镜头；开头优先实际输出前后对比，后续展示真正点击、输入、生成、检查结果的连续过程。不要拿发布会 Logo、文章滚动、静止截图充当核心内容。
- 桌面工具使用局部聚焦/裁切重排，保留完整按钮和重要字段；放大到手机能读。避免裁掉关键步骤、遮住关键输入或生成结果。
- 底部只放一层口播字幕，避开抖音底部描述栏和右侧交互区；保留视频安全边距，必要时将关键 UI 移到中上方。字幕/界面/口播涉及的价格、版本和步骤必须一致。
- 完整效果镜头给观众看清，别为了“节奏快”一秒就切掉；优先真实界面声音和稳定画面，转场简单，BGM 低于人声，不做无关科技感粒子动画。
- 没有真实录像时可用 Remotion 制作**清晰标注“示意”**的机制动画，不可把示意 UI 或效果当作真实产品录屏。不借用第三方未经允许的素材当作自己的测评。

## 5. 复用既有视频生产能力

制作前如果同一工作区存在 ../weekly-ai-news-vertical-video/SKILL.md，则读取其中**配音、画面真实与授权、成片自检、渲染和交付**相关小节作为共享制作基线，**不继承**其“多条新闻”“N分钟看完一周AI大事”等新闻特有结构。

- 默认延用用户确认过的火山引擎豆包语音合成 2.0「温暖阿虎 2.0」，speech_rate +25；不额外变速、未经同意不切换声音。接口密钥仅从既有受保护配置读取，严禁打印或写进日志和仓库；不可用则明确告知并用已获同意的备用音色。
- 口播和字幕基于同一最终稿生成；使用 TTS 时间戳/ASR 对齐；检查中英文词、数字、费用单位、产品名称读音。
- 工具可复用：Playwright 真实录屏、官方视频下载（合法可用时）、Remotion 动画与拼接、ffmpeg、Python/PIL、TTS、ASR 和视频审阅。没有相应工具时不要假装已经录屏/渲染。
- 先提供一段真实的“钩子+效果+一步操作”样片供确认；确认后按已定视觉与声音全片执行。用户要求一口气完成时，直接执行到自检和交付。
- 交付遵循既有 Skill 的原画质附件/用户指定位置、相对路径素材包、文件名和位置说明。不改动周报已有已认可画面、配音和素材规则。

## 6. 发布前验收（必须自查，除非用户明确免除）

- **真实性**：入口和新闻是两个正确链接；日期、地区、费用、可用性可追溯；亲测与宣传清楚区分；无虚构“一键完成”“永久免费”等卖点。
- **实用性**：普通观众看完知道**为什么用、在哪用、怎么用、有什么限制**；重点镜头有实际内容变化。
- **画面**：开场真实结果可辨、演示过程不断裂、前后对比一致、无黑帧/重复静帧/裁字、字幕可读、不压操作控件、没有泄漏隐私。
- **声音**：配音音色/语速一致、读音准确、声音与操作过程同步、BGM 不抢人声。
- **可发布性**：封面与内容一致、不把邀测当公测、不夸大成本节省、不重复周报；作品说明能给出用户真的能点开的官网入口。
- **实测失败时**：不得强行交付“成功实测视频”；换候选，或降级为明确标注“官方演示/尚未亲测”的资讯，告诉用户缺口。
