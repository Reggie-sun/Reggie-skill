# Weekly Report

## Overview

这个 skill 用来把零散的提交记录、memory、会话进展和用户补充要求，整理成一版能直接发出去的周报。

默认目标不是写“工程流水账”，也不是写“管理口号”，而是写清楚这周做了什么事情。

## When To Use

在这些场景下使用：

- 用户说“根据 git 记录和 memory 写周报”
- 用户要“领导能看懂”的周报
- 用户要把最近一周工作整理成自然语言汇报
- 用户已经反复调整周报口吻，希望把这些偏好固化下来

如果用户只是要日报、复盘、PR 总结、发布说明、会议纪要，不默认使用这个 skill。

## Default Style

- 默认中文输出
- 默认只写“做了什么事情”，不主动写指标、百分比、提交次数、通过率、阶段判断
- 默认不用第一人称
- 默认不用 `#` 这类 Markdown 标题
- 默认减少工程黑话和 AI 腔
- 默认按 3 到 5 个工作主题归纳，不要按 commit 顺序罗列
- 默认把技术动作翻成能看懂的话，但不要脱离事实乱拔高

## Adjustable Style Switches

如果用户明确提出以下要求，按要求覆盖默认值：

- “以我的身份写”：改成第一人称
- “把我去了”或“直接写做了什么”：改成中性表述
- “不要说指标”：删除数字化结果、次数、比例、阶段判断
- “这些 # 不要了”：改成纯文本标题和普通段落
- “领导能看懂”：进一步减少术语，把技术细节翻成结果导向的表达
- “加入某个点也写进去”：把该能力点自然并入现有段落，不单独硬插一句

## Workflow

### 1. Gather The Real Work

优先从这些来源提取内容：

- `git log`
- 当前仓库相关 memory
- 已有周报或同类文档
- 用户在本轮点名要求补进去的事项

只写有证据支持的内容。不要为了让周报“更完整”去编造进展。

### 2. Group The Work

把内容归纳成几个最容易理解的主题，通常是：

- 问答准确性或核心能力优化
- 前端或用户体验优化
- 路由、follow up、诊断、验证这类支撑能力
- 新能力底座建设

如果某个新增点本质上属于已有主题，例如 `LLM` 问题回答路由、follow up 判断记录，就直接揉进对应段落，不要为了凑结构单独拆出太多小节。

### 3. Write For Readability

每一段优先回答：

1. 这周做了什么事情
2. 主要处理的是哪类问题
3. 做完之后这块变得更顺在哪里

避免下面这些写法：

- 过度强调“阶段性成果”“关键里程碑”“稳定交付”
- 堆术语，不解释用户能感知到什么
- 先写抽象价值，再补具体动作
- 一段里塞太多细碎点

### 4. Keep The Tone Natural

默认写得像一个正常同事在汇报工作，不像模型在凑总结。

优先使用：

- “本周主要处理了……”
- “这一块主要补了……”
- “针对……做了一轮收口”
- “同时也补了……”

少用：

- “赋能”
- “闭环”
- “显著提升”
- “阶段性突破”
- “为后续奠定坚实基础”

## Output Shape

默认输出结构：

1. 一行纯文本标题，例如 `周报 2026.06.07 ~ 2026.06.13`
2. 一段总述，概括这周主要做了哪几类事情
3. `本周进展`
4. 3 到 5 段正文，每段围绕一个主题

默认不要使用：

- `#` / `##`
- 统计区
- 风险区
- 下周计划

只有用户明确要求时，才补这些部分。

## Hard Rules

- 不要把提交次数、通过率、覆盖率、百分比当成默认内容
- 不要把未验证的计划写成已经完成的工作
- 不要把每个 commit 直接翻译成一句周报
- 不要为了显得专业而引入多余术语
- 不要把用户临时加的补充点漏掉
- 不要把新增点生硬拼接成一句“另外还做了……”，优先融入相关主题

## Example Adaptations

- 用户说“以我的身份写”
  - 改成“本周主要处理了……”“这周补了……”

- 用户说“把我去了，直接写做了什么事情”
  - 改成“本周主要围绕……做了几类工作”

- 用户说“就说做了什么事情不要说指标”
  - 删掉提交次数、修复数量、通过率、阶段判断

- 用户说“加入了 llm 问题回答路由写进去和在 follow up 加入判断记录也写进去”
  - 把 `LLM` 问题回答路由写进“问答准确性相关优化”
  - 把 follow up 判断记录写进“路由 / 连续追问支撑能力”或并入对应段落

## Quick Check

写完后，默默检查这三件事：

1. 读起来像不像真实同事写的周报
2. 有没有把“做了什么”写清楚
3. 有没有混入用户已经明确不要的东西，比如指标、`#` 标题、第一人称
